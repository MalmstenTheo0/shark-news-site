# Shark News — site

Static site that publishes the daily tech digest curated by **Shark Agent** (a self-hosted [Hermes](https://github.com/NousResearch/hermes-agent) instance). The agent produces data; this repo turns it into a page.

Experiment notes, the curation prompt and the agent setup live in the I+D repo under `experiments/hermes-automated-news/`.

## How it works

```
shark-news-data  ◀──push── Shark Agent   (deploy key lives here, and only here)
       │
       └──checkout──▶ CI in this repo: validate → assemble → GitHub Pages
                              ▲
                      site code (this repo)
```

- **[shark-news-data](https://github.com/MalmstenTheo0/shark-news-data)** — a separate repository holding nothing but `data/YYYY-MM-DD.json`, one file per day. The agent's deploy key grants write access **to that repository only**.
- **This repo** — site code, schema and workflow. The agent holds no credential for it, so it cannot change what runs in a visitor's browser.
- **CI** (`.github/workflows/publish.yml`) validates every digest against [`schema/digest.schema.json`](schema/digest.schema.json) and fails the run on any violation — a bad file never reaches the published site, which simply stays as it was.

Why two repositories rather than two branches: a GitHub deploy key is scoped to a repository **by design**, so repository separation is the platform's real security boundary. Branch-level protection is not — a write-enabled deploy key inherits repository-role bypass and can push to a protected branch anyway (we confirmed this in practice before switching). The agent reads untrusted content from the internet, so it is treated as an untrusted producer: everything with consequences sits behind a boundary it has no key for, plus a deterministic validation gate.

## The contract

The agent writes one file per day, `data/YYYY-MM-DD.json`:

```json
{
  "schema_version": 1,
  "date": "2026-07-23",
  "generated_at": "2026-07-23T10:53:00-03:00",
  "summary": "Resumen del día, también usado en la notificación de Slack.",
  "items": [
    {
      "title": "Título original, sin traducir",
      "summary": "Dos o tres líneas en español.",
      "url": "https://…",
      "category": "ai",
      "source": "Hacker News"
    }
  ]
}
```

`category` is a closed set: `ai`, `dev`, `devops`, `cloud`, `security`. Bump `schema_version` if the shape ever changes, so older archived files stay readable.

CI rejects: unknown fields, missing fields, non-`https` URLs, categories outside the enum, over-long strings, markup characters (`<`, `>`) anywhere, more than 12 items, and a filename that disagrees with the `date` field.

`index.json` is **generated by CI** from the files present — never written by the agent, so it can't be used to hide or fake days.

## The site

Visual language borrowed from Smartory (the "Summer Ocean Breeze" palette), so Shark News reads as part of the same family. One column, editorial masthead, a dateline that doubles as edition navigation, and a responsive card grid.

- **Light by default, dark opt-in.** The toggle persists in `localStorage`; `assets/theme.js` runs synchronously in `<head>` so a returning reader never sees a flash of the wrong theme. It is a separate file rather than an inline script so the strict CSP needs no `'unsafe-inline'`.
- **Edition navigation.** Previous/next plus a jump-to-day select. `days[0]` is the newest edition, so "next" is disabled on the latest one — a future date is unreachable by construction, and the index is also filtered against today's date defensively.
- **Shareable state.** The hash carries both edition and filter: `#2026-07-24` or `#2026-07-24/security`. Left/right arrow keys move between editions.
- **Accessibility.** Skip link, semantic landmarks, `h1`–`h3` outline, `aria-pressed` filters, `aria-live` status, visible focus rings, 2rem minimum touch targets, and `prefers-reduced-motion` honoured.

## Local preview

Point the build at any directory holding `YYYY-MM-DD.json` digests — typically a local clone of the data repo:

```bash
python -m pip install jsonschema
git clone https://github.com/MalmstenTheo0/shark-news-data.git ../shark-news-data
python scripts/build.py --data ../shark-news-data/data --out _site
python -m http.server 8765 -d _site
```

Then open `http://localhost:8765`. `fetch` needs a real server, so opening `index.html` from disk will not work.

`_site/` is throwaway build output — the assembled site, exactly what CI uploads to Pages. It is git-ignored; delete it any time and rebuild.

This repository is code-only by design: digests live in [shark-news-data](https://github.com/MalmstenTheo0/shark-news-data), so agent output can never be mistaken for site code.

## First-time setup

Run once, from this directory.

**1. Create `main` with the site code:**

```bash
git init -b main
git add .
git commit -m "Shark News site: skeleton, schema and publish pipeline"
git remote add origin git@github.com:<user>/shark-news-site.git
git push -u origin main
```

**2. Create the companion data repository** (public, so CI can check it out without a token):

```bash
gh repo create shark-news-data --public --description "Daily digests published by Shark Agent"
```

Seed it with an empty `data/` directory (a `.gitkeep` — the build ignores dotfiles). It starts empty on purpose: the site's history should contain only editions the agent actually produced. The first CI run publishes an "aún no hay ediciones" state, and the first real edition appears when the cron fires.

**3. In THIS repo's settings:**

- **Pages** → Source: **GitHub Actions**.
- **Deploy keys** → none. The agent must have no credential here.

**4. In the DATA repo's settings:**

- **Deploy keys** → add the agent's public key **with write access**. Being repo-scoped, it cannot reach the site code.

> Do not try to solve this with a protected branch in a single repo instead. A write-enabled deploy key inherits repository-role bypass and pushes straight through a ruleset — verified in practice. Repository separation is the boundary GitHub actually enforces.

## Security notes

- No dependencies, no build step, no `node_modules`: nothing in the supply chain to audit, and what is in `main` is exactly what is served.
- Content is rendered with `textContent` only — never `innerHTML`. The schema check is the first XSS barrier, this is the second.
- A `Content-Security-Policy` meta tag restricts everything to `'self'`; there are no external scripts, styles or fonts.
- External links carry `rel="noopener noreferrer"`.
- Worst realistic case of a compromised agent: one day of odd news text, reverted with a single commit. It cannot alter the site's code or reach any other repository.
